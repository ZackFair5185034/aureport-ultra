## 技术债务清理计划

> 优先级说明：🔴 高 | 🟡 中 | 🟢 低

### 🔴 高优先级（影响生产稳定性）

| 问题 | 描述 | 建议方案 | 计划版本 |
|------|------|----------|----------|
| 缓存无容量/过期限制 | `DefaultMemoryReportDefinitionCache` 使用无限制 HashMap，生产环境可能导致 OOM | 引入 Caffeine 缓存或 Redis，支持 LRU/TTL | v1.2.0 |
| SQL 执行无超时保护 | `ReportBuilder.buildDatasets()` 执行 SQL 无 timeout，慢查询会阻塞构建线程 | 添加 `queryTimeout` 配置参数 | v1.2.0 |

### 🟡 中优先级（影响可维护性）

| 问题 | 描述 | 建议方案 | 计划版本 |
|------|------|----------|----------|
| 异常处理粒度粗 | 多处 `catch` 块直接 `throw new ReportException(ex)` 或空 `catch` 吞掉异常 | 完善异常信息链，增加具体错误码 | v1.3.0 |
| 缺少 API 文档 | 12 个 Controller 缺少 Swagger/OpenAPI 文档 | 引入 springdoc-openapi，添加 `@Tag` 注解 | v1.3.0 |
| 数据库连接资源泄漏风险 | `buildDatasets()` 的 finally 块中 `conn.close()` 若 `getConnection()` 抛异常则不执行 | 改用 try-with-resources 模式 | v1.3.0 |

### 🟢 低优先级（代码质量改进）

| 问题 | 描述 | 建议方案 | 计划版本 |
|------|------|----------|----------|
| 前端状态管理类型安全 | `stores/report.ts` 使用 `as Record<string, unknown>` 绕过了 TypeScript 静态检查 | 重构为明确的接口定义 | v1.3.0 |
| 单元格依赖检测性能 | `Context.nextUnprocessedCells()` 对 `unprocessedCellsMap` 进行 O(n) 线性扫描 | 考虑使用优先队列优化 | v2.0.0 |
| 核心循环异常保护 | `ReportBuilder.buildReport()` 的 do-while 循环无最大迭代次数保护 | 增加 `MAX_ITERATIONS` 常量保护 | v1.3.0 |
